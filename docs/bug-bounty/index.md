# Bug Bounty Intelligence

A public research hub for learning responsible disclosure, understanding program rules and improving the quality of vulnerability reports.

## Discover programs

- [HackerOne Hacktivity](https://hackerone.com/hacktivity)
- [Bugcrowd Programs](https://bugcrowd.com/programs)
- [Intigriti Programs](https://www.intigriti.com/programs)
- [YesWeHack Programs](https://yeswehack.com/programs)
- [Open Bug Bounty](https://www.openbugbounty.org/)

Always read the individual program's current scope, exclusions, safe-harbor terms, rate limits and disclosure policy. A platform listing does not mean every asset or technique is authorized.

## Research workflow

1. Select a program and save its current scope and policy.
2. Build an asset inventory using permitted discovery methods.
3. Prioritize likely security boundaries and high-impact workflows.
4. Validate findings using test accounts and non-sensitive data.
5. Preserve concise, reproducible evidence.
6. Check duplicates and program-specific reporting requirements.
7. Submit privately through the program's official channel.
8. Follow coordinated disclosure and avoid public disclosure before permission.

## Report quality checklist

- Clear title and affected in-scope asset.
- Preconditions and required role.
- Numbered reproduction steps.
- Expected versus actual behavior.
- Minimal sanitized request/response evidence.
- Verified security impact.
- CWE and CVSS vector where justified.
- Practical remediation.
- No unrelated user data or secrets.

## Responsible disclosure

Do not access, modify, download or retain data belonging to other users. Stop when impact is demonstrated. Follow the program's safe-harbor and disclosure terms and report through the designated channel.
