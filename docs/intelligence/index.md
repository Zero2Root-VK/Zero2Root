The Intelligence area is planned to connect vulnerability records with the products, weaknesses, advisories and research around them.

## Planned coverage

<div class="grid cards" markdown>

-   **CVE records**

    Vulnerability identifiers, descriptions, affected products and version ranges.

-   **CWE classifications**

    Weakness categories and relationships between recurring vulnerability patterns.

-   **GitHub Security Advisories**

    Published advisories, affected packages and remediation references.

-   **CVSS context**

    Severity scores, vector details and scoring provenance.

-   **EPSS context**

    Exploit prediction probability where reliable data is available.

-   **Exploit references**

    Public proof-of-concept references and remediation guidance, with source attribution.

</div>

## Data quality principles

Every record should retain its source, publication date and update context. Scores and exploit references should be presented with their provenance rather than treated as independently verified findings.

For now, use the existing [Vulnerability Assessment learning material](../level-1/03-vulnerability-assessment.md).
